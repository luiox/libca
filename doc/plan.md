# 基于 STM32 与 Qt 的远程升级 (OTA) 系统开发计划

## 1. 项目概述
本项目旨在实现一套高可靠、可复用的嵌入式设备远程升级系统。核心组件将封装在 `em_ota` 模块中，支持 Xmodem/Ymodem 协议，具备双向固件升级（AAB 分区）与自动回滚功能。

## 2. 开发阶段划分

### 第一阶段：基础组件完善 (em_base & em_crypto)
*   **目标**：确保底层工具链稳定。
*   **关键任务**：
    *   完善 `ringbuffer`：用于日志异步写入和协议数据缓冲。
    *   完善 `crc`：提供 CRC16 (Xmodem/Ymodem 使用) 和 CRC32 (固件校验)。
    *   完善 `string_util`：支持日志格式化输出。

### 第二阶段：通用传输协议层 (em_protocol)
*   **目标**：实现硬件无关的传输协议。
*   **关键任务**：
    *   **Transport 抽象**：定义 `read/write/flush` 接口。
    *   **Xmodem/Ymodem 状态机**：实现非阻塞的协议逻辑，支持文件名和大小传输。
    *   **单元测试**：在 PC 环境下模拟串口/网络流进行协议闭环测试。

### 第三阶段：轻量级日志系统 (em_log)
*   **目标**：替代 EasyLogger，实现自定义可扩展日志库。
*   **关键任务**：
    *   **多后端支持**：支持 UART 输出和 Flash 存储。
    *   **异步写入机制**：利用 `ringbuffer` 和低优先级任务减少对业务的影响。
    *   **异常现场记录**：设计专门的 Flash 区域记录系统崩溃信息。

### 第四阶段：分区管理与 OTA 逻辑 (em_ota)
*   **目标**：实现 OTA 核心业务逻辑。
*   **关键任务**：
    *   **Partition Manager**：管理内部 Flash 与外部 W25Q64 的分区表。
    *   **AAB 升级逻辑**：实现 Bootloader 与 App 的互备份与跳转逻辑。
    *   **原子操作保障**：确保升级过程中掉电不会导致设备“变砖”。

### 第五阶段：硬件驱动与系统集成 (em_driver & FreeRTOS)
*   **目标**：在 STM32F103RCT6 上落地。
*   **关键任务**：
    *   **Flash 驱动**：适配 STM32 内部 Flash 和 W25Q64。
    *   **ESP8266 适配**：封装 AT 指令集为流式接口。
    *   **多任务协同**：在 FreeRTOS 中部署数据采集、上报与 OTA 任务。

### 第六阶段：Qt 上位机开发
*   **目标**：实现可视化管理与固件分发。
*   **关键任务**：
    *   **网络通信**：基于 TCP 与下位机交互。
    *   **协议对接**：实现上位机侧的 Ymodem 发送逻辑。
    *   **固件管理**：版本控制与批量升级调度。

## 3. 模块详细说明

| 模块名称 | 职责描述 | 关键技术点 |
| :--- | :--- | :--- |
| **em_protocol** | 负责固件数据的可靠传输 | 状态机设计、超时重传、Transport 抽象 |
| **em_log** | 记录系统运行状态与错误日志 | 异步缓冲、FatFs 集成、日志分级 |
| **em_ota** | 升级流程控制与分区管理 | 分区表设计、版本校验、回滚逻辑 |
| **em_driver** | 硬件底层适配 | SPI/UART 驱动、Flash 读写算法 |
| **Qt App** | 用户交互与设备管理 | Qt Network, 多线程文件读取 |

## 4. 风险点与对策
1.  **掉电安全性**：通过双标志位和备份区校验确保 Bootloader 始终可用。
2.  **传输效率**：在 ESP8266 上优化 TCP 窗口大小与 Ymodem 包大小。
3.  **内存限制**：STM32F103RCT6 内存有限，需严格控制 `em_log` 和协议栈的静态内存占用。
