## 批次 2：快速组合件（已交付，分支 `feat/batch-2`）

三项全部完成，与原计划的差异两处：

1. **crypto P0**：SHA-512/SHA-384（照 sha256 结构）→ HMAC-SHA1/SHA512 补齐家族 →
   HKDF（RFC 5869）→ PBKDF2-HMAC-SHA256（RFC 8018）。✅ 全部落地，官方向量经
   python hashlib/hmac 交叉验证后入库。
2. **core：Bytes varint/zigzag**：`put_var_u32/u64`、`get_var_u32/u64`（Underflow 走
   现有 BytesError）、zigzag 编解码助手。✅ 落地；非规范编码新增
   `BytesError::MalformedVarint` 报错（原计划只复用 Underflow，实现时发现无法区分
   截断与坏数据，追加枚举值）。
3. **配置中心**：✅ 落地为新模块 `config`。与原计划差异：
   - 中间格式用 **JSON**（复用现有 json 模块 `JsonReader`）而非自写 YAML 片段解析器，
     免维护一个解析器，依赖 core/json/fs 纯向下；
   - 原计划的"落地后先接 log 级别热更新"**不做直接接线**：log 与 config 同属上层，
     库内直接依赖违反同层无依赖约束，热更新示例降级为文档用法（应用层自行桥接）。

## 批次 3：痛点清除（已交付，分支 `feat/batch-3`）

三项全部完成 + 技术债一项：

1. **str 编码内置化** ✅：Tier1（UTF 家族/Latin-1/CP1252）纯算法内置；GB18030 表经
   `tools/gen_charset_tables.py`（python codec 全量自洽校验）生成入库，构建不依赖
   python/网络；三级查找 + `supported()`/`list_supported()`；`with_iconv=n` 纯内置
   构建。验收达成：GBK 固定向量跨平台断言，不依赖 gconv。**行为变更两处**
   （GBK 0x80 严格语义、utf8→gbk 增补平面输出四字节，见 CHANGELOG）。
2. **TlsStream** ✅：net 新增 mem-BIO 适配层（包装任意 io::Reader/Writer），安全默认
   值全落地（证书校验/主机名验证默认开、SNI、TLS1.2 下限、错误分类）；http 行为等价
   切换（回归 76/76）；内存流自环单测不起网络；无 OpenSSL 时 stub。
3. **net SockUtil 增量** ✅：`get_local_ip`、keepalive 三参数（Windows 两参差异注明）、
   `interface_list`、`CachedDnsResolver`（可注入时钟/resolver）。**http 未接线**——
   解析在 `TcpStream::connect` 内部，接入需给 net connect 加 resolver 注入点，
   移到批次 4 顺手项（接入形态见 net 设计文档 12.1）。
4. **技术债** ✅：`.clang-format` 对齐规则口径（K&R Attach、120 列），存量不做重排。

性能基准（`libs/perf` 组，不进 CI）：`libca_str_perf`（utf8→gb18030 ~78 MB/s 等）、
`libca_net_perf`（TLS mem-BIO 自环 ~40 MiB/s、握手 ~460 次/秒）、
`libca_net_sock_perf`（DNS 缓存命中 ~140ns，为未命中的 1/8）。

## 批次 4：结构增强

0. **顺手项：http 接 CachedDnsResolver**：按 net 设计文档 12.1 的注入形态，
   `HttpClientOptions` 加可选 `std::shared_ptr<CachedDnsResolver>`（默认不注入行为
   不变），连接路径把缓存 resolver 传给 net connect 的注入点。
1. **thread MessageLoop**：线程亲和任务循环——`post_task` / `post_task_and_reply` /
   `post_delay_task`（延迟任务可落在批次 1 的 TimerManager 上）。这是 event loop 的
   前身，异步化路线第一块砖。
2. **process IPC 容错**：写者进程探活（崩溃后读者接管）、环形槽语义增强（Morn
   morn_message.c 思想，只学设计）。
3. **crypto P1：AES**：内置参考实现 AES-128/192/256 ECB/CBC/CTR（文档明示不承诺
   常量时间）+ `--with_openssl` / `--with_cng` 后端选择骨架 + 双实现对拍测试。
   AES-GCM 只做外部后端。随后可按需开 schannel（Windows 零依赖 TLS）后端。

## 明确不做（防返潮，讨论已结论）

- **Fiber / 栈式协程**：库偷偷转 fiber 模式对嵌入方是敌意行为；异步未来 =
  MessageLoop → event loop（按需）→ C++20 协程壳。
- **RSA / DES / RC4 新用途**：需要 RSA 时走 OpenSSL 后端。
- **零拷贝 Buffer 抽象 / ByteArray 链式架构**：Bytes 三件套已覆盖，varint 补齐即可。
- **ORM 代码生成**：C++17 无反射，工具链维护成本 > 收益。
- **util 大杂烩模块**：杂件按落位原则归现有模块（utility/reflect 前车之鉴）。
- **ICU / 自写 TLS 协议栈**：编码用 WHATWG 表自给，TLS 只做成熟后端适配层。
