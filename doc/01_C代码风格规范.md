# C语言编码风格规范 

## 1. 核心原则
- **类型安全**：严禁依赖平台相关的原生类型。
- **明确性**：尽可能使用明确长度的`i32`替代原生的`int`。
- **可读性**：代码应自解释，命名必须准确。



## 2. 文件组织

- **命名**：全小写 + 下划线 (snake_case)。
  - 正例: `ringbuffer.c`, `crc.c`
  - 反例: `RingBuffer.c`, `CRC.c`
- **Header Guard**：统一使用 `#ifndef` 宏保护，禁止使用 `#pragma once`（部分嵌入式编译器支持不佳）。
  - 格式：`#ifndef FILENAME_H`
- **Include 顺序**：
  1. 对应的 `.h` 文件
  2. 项目内部模块头文件
  3. 标准库头文件



## 3. 类型系统

**禁止使用原生裸类型**（如 `int`, `unsigned long`, `char` 等），全部使用标准定长类型。

**命名逻辑**：
- **有符号整数**：以 `i` (int) 开头，后接位数。如 `i8`, `i16`, `i32`, `i64`。
- **无符号整数**：以 `u` (unsigned) 开头，后接位数。如 `u8`, `u16`, `u32`, `u64`。
- **浮点数**：以 `f` (float) 开头，后接位数。如 `f32`, `f64`。

| 语义         | 类型  | 说明                      |
| ------------ | ----- | ------------------------- |
| 整数         | `u8`, `i8`, `u16`, `i16`... | 见上述命名逻辑 |
| 大小/索引    | `usize`| 代替 `size_t`             |
| 布尔         | `bool`| 必须包含 `<stdbool.h>`     |

*注：所有类型仅需包含 `datatype.h` 即可获得。*



## 4. 命名规范

### 4.1 变量
- **局部变量**：`snake_case`。如 `user_id`, `temp_buffer`。
- **全局变量**：`g_` 前缀。如 `g_crc_table`, `g_system_state`。
- **常量/宏**：全大写 + 下划线。如 `MAX_BUFFER_SIZE`, `PI`。



### 4.2 函数

以小写加下划线命名，oop设计时，需要`对象类型_方法名`。

接近函数行为的宏，应该以函数的方式来命名，其他情况下以宏常量那种全大写命名。



### 4.3 结构体/枚举

- **名称**：全小写 + `_t` 后缀。
- **结构体标签**：**禁止使用匿名结构体**。必须提供结构体标签（tag），标签名通常为类型名去掉 `_t`。
- **使用偏好**：在代码中**尽可能使用带 `_t` 的类型名**，仅在结构体内部自引用或前置声明等必须场景下使用 `struct 标签`。
- **示例**：
  ```c
  // 定义
  typedef struct node { 
      struct node *next;  // 必须使用 struct 标签进行自引用
      u32 data;
  } node_t;

  // 使用
  node_t my_node;        // 正例：使用 _t 后缀的类型名
  struct node my_node;   // 反例：除非特殊情况，否则不推荐直接使用 struct 标签
  ```
- **原因**：保持代码简洁一致，符合抽象封装的原则。



## 5. 格式与排版

- **缩进**：4 个空格，禁止使用 Tab。
- 剩下参考`.clangformat`文件，对于需要保持代码格式的宏定义，一定要像下面这样子包起来

```c
// clangformat off

宏定义

// clangformat on

```
