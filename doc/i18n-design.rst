.. _i18n-design:

CLI 消息国际化设计
==================

i18n 将 CLI 消息表编入消费 target，启动时注册生成的表，运行时查找译文和替换位置占位符。源语言文件只在构建时需要，二进制可以单独分发。

.. _i18n-design-build-rule:

语言文件到生成头
----------------

xmake rule ``libca.i18n.embed-lang`` 从输入文件的同一目录读取 UTF-8 的 ``.lang`` 文件。每个 target 使用一组语言文件，按文件名识别 locale。规则校验 locale 文件名和点分层的消息键，拒绝同一语言中重复的键。每组必须包含 ``zh_CN``，其余语言的键必须是该组中文表的子集。此约束允许翻译逐步补齐，并在构建时发现错误拼写或失去来源的翻译。

规则按文件名和键排序，将翻译字面量、语言表与表组写入 target 的 autogen 头文件。它将生成目录加入 include 搜索路径，登记语言文件依赖，并在生成内容不同时更新头文件。每个表组可由消费方显式注册，允许共享库和产品分别生成各自的语言表。

.. _i18n-design-lookup:

注册与回退
----------

注册阶段把各表组的条目合并为按语言分组的有序键索引，后注册表中的同语言同键覆盖先前表的消息。启动时可先根据配置的环境变量选择语言，再由参数预扫描应用 ``--lang``。注册和语言选择应先于并发查询完成。

查找先用当前语言，再回退到 ``zh_CN``，仍无消息时显示原键。该顺序允许未翻译或尚未纳入消息表的文案继续显示。位置占位符按译文中的顺序展开，翻译可重排或重复参数。
