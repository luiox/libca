.. _zip-design:

ZIP 归档设计
=============

ZIP 模块提供两种读取视图。随机访问从 central directory（CEN）建立条目索引，顺序读取从 local file header（LOC）开始逐项处理。这两种视图服务于不同读取场景，前缀恢复和 ZIP64 兼容归随机访问路径。

.. _zip-design-eocd:

从归档末尾定位目录
------------------

随机访问先在文件末尾的 22 + 65535 字节范围内反向搜索 end of central directory（EOCD）。候选必须同时满足签名正确且固定记录与声明的注释长度正好抵达文件末尾。此规则优先选择最靠近尾部且长度自洽的记录，避免把前置归档的结束记录当成当前归档目录。选定后再验证目录结构，结构损坏按解析失败处理。

CEN 给出条目名、压缩方法、尺寸、CRC32 和 LOC 偏移。索引保留 CEN 顺序并支持按名称查找，读取条目时再按 LOC 定位数据并校验解压结果。将目录解析和数据读取分开，使列举条目无需解压归档中的文件。

.. _zip-design-prefix:

前缀拼接与偏移恢复
------------------

自解压文件或内嵌归档可以在 ZIP 前携带额外字节，目录与条目的偏移仍可能相对于 ZIP 段起点。随机访问先验证记录给出的目录偏移。目录签名、文件范围或结束位置不符时，以结束记录位置减去目录尺寸求出目录起点。传统 ZIP 以 EOCD 为结束锚点，ZIP64 以 ZIP64 EOCD 为锚点。恢复后的 CEN 仍须通过签名与边界校验。

实际 CEN 起点与记录中 CEN 偏移的差值是整段归档的偏移修正量。读路径把同一修正量加到每个条目的 LOC 偏移上，使目录和数据使用同一坐标系。顺序读取按当前游标读取 LOC，不走尾部索引和前缀恢复。

.. _zip-design-zip64:

ZIP64 读写边界
--------------

随机访问在 EOCD 的条目数、目录尺寸或目录偏移出现全一哨兵时读取 ZIP64 locator 和 ZIP64 EOCD。locator 的原始偏移优先使用，偏移失效时向前寻找尺寸自洽且不与 locator 重叠的记录，以支持带前缀的 ZIP64 文件。CEN 中的尺寸或 LOC 偏移出现全一哨兵时，只从 ZIP64 extra field 取回对应字段。ZIP64 结束记录路径只支持单盘。

该路径兼容使用 ZIP64 元数据表示的归档，但归档仍整体载入内存，条目模型中的压缩尺寸、解压尺寸和修正后的 LOC 偏移仍受 32 位范围限制。写路径按 LOC、数据、data descriptor 的顺序写出，在关闭时追加缓存的 CEN 和传统 EOCD。它不生成 ZIP64 记录，也不能用来保证超出传统 ZIP 字段范围的输出可读。当前传统输出恰有 65535 个条目时，EOCD 的计数值也会被随机访问读路径识别为 ZIP64 哨兵，缺少 locator 会导致读取失败。
