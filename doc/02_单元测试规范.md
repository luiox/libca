# 单元测试规范

## 1. 测试架构
- **测试框架**：自研轻量级 Doctest 风格框架 (基于宏自动注册)。
- **测试位置**：**测试代码必须与实现代码位于同一个 `.c` 文件中**（自包含测试）。
- **隔离机制**：使用 `TEST_ENABLE` 宏控制测试代码的编译。



## 2. 测试代码结构

所有测试必须写在源文件底部：

```c
/* — 实现 — */
int add(int a, int b) { return a + b; }

/* — 测试 — */
#if TEST_ENABLE

#include “../em_test/test.h”

TEST_CASE("add_positive_numbers") {
    int res = add(1, 2);
    TEST_ASSERT_EQUAL(3, res);
}

#endif
```



## 3. 用例命名规范

- **格式**：`<module>_<function>_<scenario>`
- **原则**：名称必须清晰描述测试场景。
  - ✅ `crc32_ieee_standard_string`
  - ✅ `queue_push_when_full`
  - ❌ `test1`, `check_queue`



## 4. 断言使用

- **通用相等**：使用 `TEST_ASSERT_EQUAL(expected, actual)`。
- **十六进制/位运算**：必须使用 `TEST_ASSERT_EQUAL_HEX(expected, actual)`。
  - 适用于：CRC 结果、哈希值、寄存器值。
- **指针/内存**：使用 `TEST_ASSERT_EQUAL_PTR(expected, actual)`。



## 5. 测试覆盖要求

- **标准向量**：所有算法模块（CRC, Hash, 加密等）**必须**包含标准测试向量的测试（例如 "123456789" 的 CRC 结果）。
- **边界测试**：必须测试边界情况（0, 1, MAX_SIZE）。
- **错误处理**：如果函数可能返回错误码，必须编写对应的失败测试用例。



## 6. 集成与构建

- **Xmake 集成**：
  - 普通编译目标：不定义 `TEST_ENABLE`。
  - 测试目标：定义 `TEST_ENABLE`。
- **运行**：
  - `xmake test -g <group>`: 执行分组测试。
  - `xmake run <target>`: 查看详细失败日志。
