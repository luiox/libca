# 单元测试规范

## 1. 测试架构
- **测试框架**：自研轻量级 Doctest 风格框架 (基于宏自动注册)。
- **测试位置**：**测试代码必须与实现代码位于同一个 `.c` 文件中**（自包含测试）。
- **隔离机制**：使用 `TEST_ENABLE` 宏控制测试代码的编译。



## 2. 测试代码结构

### 2.1 原子化原则 (Atomic Testing)
**核心思想**：每个 `TEST_CASE` 必须尽可能小且专一。
- **禁止**：在一个 `TEST_CASE` 中测试模块的所有功能。
- **推荐**：为每个子功能、每个数据类型、每个边界条件单独编写 `TEST_CASE`。

### 2.2 结构示例
所有测试必须写在源文件底部，并包含在 `#if TEST_ENABLE` 块中：

```c
/* — 实现 — */
void ringbuffer_write_u8(ringbuffer_t* rb, u8 value) { ... }

/* — 测试 — */
#if TEST_ENABLE

#include "../em_test/test.h"

// 正例：专一的测试用例
TEST_CASE(ringbuffer_u8) {
    u8 mem[64];
    ringbuffer_t rb;
    ringbuffer_init(&rb, mem, 64);

    ringbuffer_write_u8(&rb, 0xAB);
    TEST_ASSERT_EQUAL_INT(0xAB, ringbuffer_read_u8(&rb));
}

#endif
```



## 3. 用例命名规范

- **格式**：`<module>_<feature>` 或 `<module>_<scenario>`
- **原则**：名称必须清晰描述测试点。
  - ✅ `ringbuffer_basic` (基础读写)
  - ✅ `ringbuffer_wrap_around` (回环处理)
  - ✅ `ringbuffer_u16` (特定类型读写)



## 4. 断言使用

请根据数据类型选择合适的断言宏：

- **整数相等**：`TEST_ASSERT_EQUAL_INT(expected, actual)` 或 `TEST_ASSERT_EQUAL_UINT`
- **十六进制/位运算**：`TEST_ASSERT_EQUAL_HEX(expected, actual)` (以 0x 格式打印失败日志)
- **指针/内存**：`TEST_ASSERT_EQUAL_PTR(expected, actual)` 或 `TEST_ASSERT_EQUAL_MEMORY(exp, act, size)`
- **布尔值**：`TEST_ASSERT_TRUE(condition)`, `TEST_ASSERT_FALSE(condition)`
- **字符串**：`TEST_ASSERT_EQUAL_STRING(expected, actual)`
- **浮点数**：必须使用 `TEST_ASSERT_EQUAL_FLOAT(expected, actual, epsilon)`，严禁直接使用 `==` 比较。
  - `epsilon` 为允许的误差范围（如 `0.00001f`）。





## 5. 测试覆盖要求

- **标准向量**：所有算法模块（CRC, Hash, 加密等）**必须**包含标准测试向量的测试（例如 "123456789" 的 CRC 结果）。
- **边界测试**：必须测试边界情况（0, 1, MAX_SIZE）。
- **错误处理**：如果函数可能返回错误码，必须编写对应的失败测试用例。



## 6. 集成与构建

- **Xmake 集成**：
  - 测试的`target`名字以`test-`开头。
  - 使用`add_rules`来自动化注入测试需要的单元测试库和`main`函数。
```xmake
target("test-ringbuffer")
    set_kind("binary")
    add_files("ringbuffer.c")
    add_rules("em_test", { test_enable = true, use_default_main = true })
```
- **运行**：
  - `xmake test -g <group>`: 执行分组测试。
  - `xmake run <target>`: 查看详细失败日志。
