# libca.em_ 系列组件代码规范

本文件为 `em_driver` 代码的规范（必须遵守）。本规范面向驱动开发者与 PR 审查者，覆盖语言、类型、命名、注释、风格、参数校验、单元测试等方面。

---

## 1. 语言与兼容性
- 仅使用标准 C99。在 `.c` / `.h` 中禁止使用 C++ 语法或用 C++ 编译器编译 C 代码（除非显式说明）。
- 使用编译器扩展必须显式标注（参考 `em_base/compiler_compat.h`）。
- 对外头文件必须用下列方式包裹以兼容 C++：

```c
#ifdef __cplusplus
extern "C" {
#endif

// 公共声明

#ifdef __cplusplus
}
#endif
```

## 2. 代码质量目标
- 可靠且实用
- 可测试
- 可维护

## 3. 类型系统
- 使用 `datatype.h` 中的固定长度类型：`i8`, `u8`, `i16`, `u16`, `i32`, `u32`, `i64`（非必要尽量避免）, `u64`, `f32`, `f64`, `usize`, `bool`。
- 不直接使用 `size_t`、`uintptr_t` 等标准整数类型，除非必要；优先使用 `usize` 或明确宽度类型。
- 索引/长度/容量使用 `usize`；偏移或可能为负的差值使用 `i32`。

## 4. 命名规范
- 文件名使用 snake_case。
- 结构体类型：`struct xxx`，并提供 `xxx_t` 别名。
- 枚举类型：`xxx_enum`，并 typedef 出 `xxx_t`，属于模块的枚举，需要前缀模块名字比如`motor_mode_t`；枚举值使用大写下划线并带模块前缀以避免冲突（如 `BH1750_ERR_TIMEOUT`）。
- 函数命名：模块前缀 + 动词（例如 `bh1750_read`）。
- 宏命名：对外使用 snake_case，内部宏使用 `CA_` 前缀与全大写。
- 全局变量须以 `g_` 前缀。
- 对于源文件内私有函数（仅在当前 .c 使用），需加 `static` 修饰。
- 头文件保护：禁止使用 `#pragma once`，使用 `项目名_路径_文件名_H` 风格的宏作为保护。

## 5. 代码风格
- 缩进：仅使用 4 空格（禁止 tab）。
- 花括号风格：K&R。
- 每行最大长度：120 字符。
- 其余风格参照仓库根目录的 `.clangformat`（若与本文件冲突，以本文件为准）。

## 6. 注释规范
- 公共 API 必须使用 doxygen 注释，至少包含 `@brief`、`@param`、`@return`，注释使用中文。
- 私有函数须有注释，说明目的、前置条件与边界情况。

## 7. 代码细节规范
- 参数检查：
  - 针对 `self` 指针（如 `xxx_t *self`）等关键参数应使用契约式编程的 `param_check`（定义在 `em_base/debug.h`）。
  - 对于其他可能为 NULL 的参数或非热路径，请使用 if 判断并返回适当错误码。
- 错误码：使用 `模块名_ERR_描述` 或 `MODULE_ERR_*` 命名风格，错误码必须为负数；成功码为 `模块名_OK`（0）。
- 私有函数必须加 `static`。
- 避免使用动态内存分配（`malloc` / `free`）；优先栈分配或由调用者提供内存。

## 8. 单元测试规范
em_driver的驱动不需要写单元测试，由我自己实现硬件测试。
