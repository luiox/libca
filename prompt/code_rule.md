【libca的非em_系列组件代码库规范（必须遵守）】

【语言】
- C99（在`.c`和`.h`这两种c文件内），C++17（在`.cpp`和`.hpp`这两种c++文件内）
- 在c文件内，禁止使用c++语法，并且不要用C++编译器编译C代码，只能是用c代码的接口，对于可能要被c++使用的C接口，要以下面这个包裹
```c
#ifdef __cplusplus
extern "C" {
#endif

#ifdef __cplusplus
}
#endif
```

【注释规范 - 加一原则】
- **加一原则**：在所有编程语言中，文档注释的标记 = 该语言行注释的最小单位重复一次。例如 C/C++ 行注释 `//` 的最小单位是 `/`，文档注释即为 `///`；Lua 行注释 `--` 的最小单位是 `-`，文档注释即为 `---`；Python 行注释 `#` 的最小单位是 `#`，文档注释即为 `##`；汇编行注释 `;` 的最小单位是 `;`，文档注释即为 `;;`。
- 使用中文编写注释，但是不要把英文技术术语翻译为中文。
- **二元切分原则**：注释只分两类，不得混用。
  1. **API 注释** — 必须用 `/// ` Doxygen 行注释。适用于头文件中所有对外公开的 API 声明（类、结构体、枚举、函数、方法、公开常量、公开宏等）。参数、返回值和非平凡语义按需使用 `@param`、`@return`、`@note` 等标签。
  2. **非 API 注释** — 必须用 `//` 或 `/* */`，禁止使用 `///`。适用于文件说明、章节分隔、实现细节、测试说明、内部函数说明等所有非 API 场景。需要说明 static 内部函数时，应在定义处使用普通注释说明其输入、输出和关键逻辑。
- 头文件中的公开 API 注释是 API 使用方式的唯一事实来源；`doc/` 只记录关键架构设计、设计决策和模块组织，不重复维护 API 清单。每个模块最多一个设计文档。
- `.cpp`/`.c` 中已在头文件声明并注释的公开 API，禁止在定义处重复复制 Doxygen 注释。
